# AI 학습지원 플랫폼 아키텍처

## 1. 문서 목적

이 문서는 팀 통합의 기준 코드인 교수·학생용 PDF RAG 애플리케이션의 현재 구조와 팀 통합 기준을 정의한다.

- 현재 구현된 기능과 향후 작업을 구분한다.
- `app.py`와 `rag_module.py` 사이의 인터페이스를 명확히 한다.
- AI Engineer, Cloud Engineer, PO가 동일한 기준으로 개발·검수할 수 있도록 한다.
- 근거가 부족한 답변, API 오류, 저장소 제약에 대한 대응 기준을 정한다.

## 2. 서비스 목표와 MVP 범위

교수자가 강의자료 PDF를 등록하고 공개 여부를 설정하면, 학생이 공개된 자료를 선택하여 강의자료에 근거한 답변·쉬운 설명·퀴즈를 제공받는 서비스이다.

### 현재 MVP에 포함된 기능

- 교수자·학생 역할별 로그인과 화면 분리
- 복수 PDF 업로드·선택
- 강의자료 공개·비공개 설정과 삭제
- 선택 자료 기반 질의응답
- 강의자료 요약과 학생용 쉬운 설명
- OX 3문항·단답형 3문항 퀴즈 생성과 자동 채점
- 답변 근거 파일명·페이지·본문 일부 표시
- PDF 페이지 미리보기와 다운로드
- 역할별 복수 채팅 생성·전환·기록 저장

### 현재 MVP에서 제외하는 범위

- 실제 대학 계정 또는 SSO 연동
- 관리자 페이지와 사용자 가입
- 대규모 동시 사용자 처리
- 과목·학기별 권한 관리
- 장기 운영용 데이터베이스와 오브젝트 스토리지
- 모델 제공자 자동 전환과 복잡한 에이전트 워크플로

## 3. 현재 시스템 구성

```text
[교수자 / 학생]
       |
       v
[Streamlit UI: app.py]
  - 로그인 및 역할 분기
  - PDF·공개 설정·채팅·퀴즈 UI
  - Session State
       |
       +----------------------+
       |                      |
       v                      v
[로컬 파일 저장소]       [RAG 모듈: rag_module.py]
  - data/pdfs/             - PyMuPDF 텍스트 추출
  - documents.json         - LangChain 문서 분할
  - chat_sessions.json     - OpenAI Embeddings
                            - FAISS 검색
                            - OpenAI Chat 모델
       |                      |
       +----------+-----------+
                  v
        [답변·퀴즈·출처 반환]
```

## 4. 주요 컴포넌트

### 4.1 Entry/UI — `app.py`

`app.py`는 사용자 입력과 화면 표시를 담당한다.

- `show_login()`: 테스트 계정 인증과 역할 설정
- `show_professor_page()`: 자료 업로드·공개 설정·삭제·질문·요약
- `show_student_page()`: 공개 자료 선택·질문·쉬운 설명·퀴즈
- `activate_documents()`: 선택된 복수 PDF로 RAG 객체 준비
- `display_grouped_sources()`: 교수자용 출처 묶음 표시
- `display_student_source_excerpts()`: 학생용 근거 본문 탐색
- `display_student_sources()`: 학생용 출처 페이지 미리보기
- `display_student_downloads()`: 학생용 공개 자료 다운로드
- 채팅 세션 함수: 새 채팅 생성, 전환, 저장, 불러오기

실행 중 상태는 `st.session_state`에 저장한다. 로그인 정보, 선택 자료, RAG 객체, 답변, 채팅, 퀴즈, 패널 표시 여부가 주요 상태이다.

### 4.2 RAG Core — `rag_module.py`

`rag_module.py`는 PDF 처리, 검색, 답변·요약·퀴즈 생성을 담당한다.

- PDF 파서: PyMuPDF
- 문서 표현: LangChain `Document`
- 분할기: `RecursiveCharacterTextSplitter`
- 임베딩: `text-embedding-3-small`
- 벡터 저장소: FAISS 인메모리 인덱스
- 생성 모델: `gpt-4o`, `temperature=0`
- 퀴즈 출력 검증: Pydantic 구조화 출력

현재 문서 분할 기준은 `chunk_size=400`, `chunk_overlap=50`이다. 각 청크는 원본 파일명과 실제 PDF 페이지 번호를 메타데이터로 유지한다.

### 4.3 Local Data — `data/`

현재 MVP는 애플리케이션 폴더 아래 로컬 파일에 데이터를 저장한다.

| 경로 | 내용 | Git 관리 |
|---|---|---|
| `data/pdfs/` | 교수가 업로드한 PDF | 제외 |
| `data/documents.json` | 파일명·경로·공개 여부 | 제외 |
| `data/chat_sessions.json` | 사용자별 채팅 기록 | 제외 |

`data/`의 실행 데이터와 PDF는 `.gitignore`로 GitHub 업로드에서 제외한다.

## 5. 핵심 처리 흐름

### 5.1 PDF 등록과 활성화

1. 교수가 하나 이상의 PDF를 업로드한다.
2. `app.py`가 PDF를 `data/pdfs/`에 저장하고 문서 목록을 갱신한다.
3. 사용자가 자료를 선택하면 `activate_documents()`가 선택 목록을 확인한다.
4. `process_pdfs_and_get_chain(pdf_paths)`가 각 페이지의 텍스트를 추출한다.
5. 페이지 문서를 청크로 나누고 임베딩한다.
6. 선택 자료 전체를 대상으로 하나의 FAISS 인덱스와 `RAGChain`을 생성한다.
7. 선택 목록이 달라지면 RAG 객체를 다시 생성한다.

### 5.2 질문과 답변

1. 사용자가 질문과 선택적 언어 지침을 입력한다.
2. FAISS가 관련 청크를 최대 8개 검색한다.
3. 관련도 점수 `0.15` 이상인 청크를 우선 근거로 사용한다.
4. 짧은 질문의 핵심어가 PDF 본문에 직접 존재하면 키워드 일치 청크를 보완한다.
5. 근거가 하나도 없으면 LLM을 호출하지 않고 `has_evidence=False`를 반환한다.
6. 근거가 있으면 출처·페이지가 포함된 컨텍스트로 LLM을 호출한다.
7. 답변과 중복 제거된 출처 목록을 UI에 반환한다.

### 5.3 강의자료 요약

1. 선택한 파일별로 핵심 개념 검색 결과와 문서 전체 구간의 대표 청크를 수집한다.
2. 파일별 대표 근거를 합쳐 복습 노트 형태의 요약을 생성한다.
3. 요약에 사용한 파일명과 페이지 목록을 반환한다.

### 5.4 학생 퀴즈

1. 선택한 각 파일에서 핵심 개념·정의·원리 관련 대표 청크를 가져온다.
2. Pydantic 스키마에 맞춰 OX 3문항과 단답형 3문항을 생성한다.
3. 문항·정답·허용 정답·해설·근거 파일·페이지를 반환한다.
4. UI가 학생 답안을 정규화해 자동 채점하고 오답 근거를 표시한다.

## 6. 모듈 인터페이스 계약

팀 통합 중 아래 인터페이스는 `app.py`와 `rag_module.py`를 연결하는 기준으로 유지한다. 변경이 필요하면 두 파일과 테스트를 함께 수정한다.

### RAG 객체 생성

```python
process_pdfs_and_get_chain(pdf_paths: list[str]) -> RAGChain
```

### 일반 질문

```python
RAGChain.invoke(
    question: str,
    answer_instruction: str = "",
) -> dict
```

기본 반환 형식:

```python
{
    "answer": str,
    "sources": [
        {
            "file": str,
            "page": int,
            "score": float,
            "excerpt": str,
        }
    ],
    "has_evidence": bool,
}
```

### 요약

```python
RAGChain.generate_summary() -> dict
```

### 퀴즈

```python
RAGChain.generate_quiz() -> dict
```

퀴즈 성공 결과에는 `quiz` 목록이 추가된다. 요약·퀴즈의 `sources`는 기능 특성에 따라 `file`과 `page`만 포함할 수 있으므로 UI는 선택 필드를 안전하게 처리해야 한다.

## 7. 오류 처리와 Fallback 기준

### 현재 구현

- PDF에서 텍스트를 읽지 못하면 사용자에게 분석 불가 오류를 표시한다.
- 검색 근거가 없으면 임의 답변을 생성하지 않고 근거 부족 메시지를 반환한다.
- 짧은 질문은 벡터 검색 결과에 키워드 직접 일치 검색을 추가한다.
- 퀴즈가 OX 3개·단답형 3개 형식을 만족하지 못하면 재시도 안내 오류를 발생시킨다.
- UI의 `try/except`가 분석·생성 오류를 사용자 메시지로 변환한다.

### 다음 단계

- OpenAI 호출 실패 시 제한된 횟수의 재시도 적용 여부 결정
- 시간 초과·사용량 제한·인증 실패 오류 메시지 분리
- 배포 환경에서 오류 세부 정보는 로그에만 기록하고 사용자에게 비밀정보를 노출하지 않기
- 실제 질문 세트로 관련도 임계값 `0.15` 재검증

## 8. 보안과 개인정보

- `.env`와 `.streamlit/secrets.toml`은 Git에 포함하지 않는다.
- OpenAI API 키는 로컬 `.env` 또는 배포 플랫폼 Secrets에서 환경변수로 주입한다.
- 업로드 PDF와 채팅 기록은 GitHub에 올리지 않는다.
- 현재 로그인은 소스 코드의 테스트 계정이므로 시연용으로만 사용한다.
- 실제 서비스 전환 시 비밀번호 해시 저장, 사용자 DB, 역할 기반 접근 제어가 필요하다.
- 공개 상태가 아닌 PDF는 학생 목록·미리보기·다운로드에서 제외해야 한다.

## 9. 배포 시 고려사항

현재 로컬 파일 저장 방식은 단일 PC 시연에는 적합하지만, 클라우드 재시작·재배포 후 파일이 유지된다는 보장이 없다. 또한 여러 실행 인스턴스가 동일 파일을 공유하지 못한다.

팀은 배포 전에 다음 중 하나를 결정한다.

1. 시연용 배포: 초기화 가능성을 명시하고 로컬 저장 방식을 유지한다.
2. 운영형 배포: PDF는 오브젝트 스토리지, 메타데이터·채팅은 데이터베이스로 이전한다.

Cloud Engineer는 최종 플랫폼에서 다음을 확인한다.

- `requirements.txt` 기반 설치 성공
- 메인 실행 파일 `app.py`
- Secrets에 `OPENAI_API_KEY` 등록
- 업로드 크기와 파일 쓰기 권한
- 재시작 후 데이터 유지 여부
- 배포 URL 접속과 교수·학생 시나리오 동작

## 10. 품질 검증 기준

AI Engineer가 우선 검증할 최소 항목은 다음과 같다.

- PDF 페이지 번호 메타데이터가 실제 페이지와 일치하는가
- 텍스트가 없는 PDF에서 명확한 오류가 발생하는가
- 복수 PDF 선택 시 모든 선택 자료가 검색 대상에 포함되는가
- 근거 부족 질문에서 답변 생성을 차단하는가
- 출처의 파일명·페이지·본문 일부가 응답과 일치하는가
- 공개되지 않은 PDF가 학생에게 노출되지 않는가
- OX 3문항·단답형 3문항 형식과 출처가 유지되는가
- 새 채팅을 만들어도 선택 자료는 유지되고 대화만 초기화되는가
- 새 환경에서 `requirements.txt`만으로 실행되는가

PO는 교수자·학생 시나리오 기준으로 사용자 인수 테스트를 수행하고, 실패 항목을 GitHub Issue로 등록한다.

## 12. 현재 결정과 미결정 사항

### 확정

- 팀 기준 코드는 교수·학생용 Streamlit RAG 프로토타입이다.
- PDF 근거가 있는 답변과 출처 페이지 표시를 핵심 가치로 유지한다.
- API 키·실행 데이터·업로드 PDF는 Git에서 제외한다.
- 팀원 작업은 개별 브랜치와 Pull Request 리뷰를 통해 `main`에 병합한다.

### 결정 필요

- 최종 배포 플랫폼
- 배포 환경의 영속 저장 방식
- OpenAI 오류 재시도 정책
- 관련도 임계값의 최종 수치
- 실제 서비스용 인증 방식
